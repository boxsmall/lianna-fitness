# 练哪第二版页面设计

版本：2026-11-18 · 首轮可点击设计稿

双击 **index.html** 查看设计目录；点击任意页面缩略图进入可操作原型。手机端设计入口是 **mobile.html**，电脑后台入口是 **admin.html**。文件均使用相对路径，保留整个目录即可离线打开。

## 本次交付

- 小程序：15 个页面，覆盖今天、创建计划、周安排、当天训练、动作库、动作详情、器械、饮食资料、每日目标、今日饮食、食材搭配、收藏、个人中心、登录、训练记录。
- 管理后台：6 个业务页面，以及动作编辑、份量试算、发布与版本、角色权限 4 个相关视图。
- 独立弹窗：移动训练日、组次设置、实际完成记录、替换食材、分餐比例、内容审核、退回原因、版本回退、工单处理、规则编辑。
- `screenshots/`：各页面截图；`mobile-overview.png`、`admin-overview.png`：设计总览。

这是 HTML 交互设计稿，便于先评审页面和操作路径。微信登录、AI 推荐、个人记录持久化和生产发布不连接真实服务；刷新会恢复初始样例。原小程序、线上网站和第二版需求文档均未改动。

## 设计依据与视觉规则

依据项目中的第二版需求文档，以及已有的练哪手机界面、Logo、人物与器械素材展开。

| 决策 | 呈现方式 | 目的 |
| --- | --- | --- |
| 沿用现有视觉 | 练哪 Logo，主蓝 `#2448D8`，暖白 `#FBFAF7`，黑色标题与细灰分隔线 | 保持第一版的品牌辨识 |
| 手机先看今天 | 今天、计划、饮食、我的四个底部入口 | 把日常训练和三餐放在最短路径上 |
| 训练按日期组织 | 周列表显示日期、课程、动作摘要，编辑进入单次训练 | 调日期与改内容有清楚的操作位置 |
| 营养目标与差额一起看 | 本餐顶部同时显示目标、当前搭配和差额；食材卡显示称重口径和克数 | 换食材后不用靠记忆比较数字 |
| 后台采用桌面密度 | 左导航，顶部角色，表格目录，左右对照或试算详情 | 适合编辑、核查与发布，而非手机卡片的放大版 |
| 原版和重制并排 | 动图同框展示，说明文本在下，器械和排课属性在右 | 将图文核对和属性审核放在同一页面 |
| 状态使用文字与色彩共同区分 | 待审核、已发布、失败说明、权限反馈 | 不单靠颜色表达可用状态 |

手机按 390 × 844 设计，检查了 375、390、430 像素宽度。后台主画布为 1440 像素宽，定位为电脑端运营工具。

## 建议体验路线

1. **计划：** 创建计划 → 演示微信登录 → 选择目标／天数／时长 → 生成 → 移动周三训练到周四 → 再移到已有课的周五 → 编辑 → 换动作 → 侧平举改为 2 组 × 12 次。默认仅影响所选动作和本次训练；选择后续范围会更新样例中后续的同一动作。
2. **饮食：** 填性别、身高和体重 → 每日目标 → 午餐 → 主食填写 150 克并锁定 → 鸡胸肉换为瘦牛肉 → 看保留的米饭重量和新的肉量、营养差额。日目标与分餐比例也可调整。
3. **收藏：** 挑动作 → 热身 → 站姿踝关节绕环 → 收藏 → 我的收藏 → 臀腿。热身候选不受器械过滤影响，列表标明收藏所属部位。
4. **后台：** 训练计划 → 15 分钟失败样例；食材 → 份量试算；发布 → 切换「内容运营」尝试发布 → 切换「审核人员」发布或填写原因回退。

## 演示范围

本轮聚焦页面结构和关键操作：

- 动作库引用 10 个项目样例，含 2 个热身；统计中的 1,324 表示现有全库规模，不表示原型载入了全库。
- 自动排课使用固定示例模板展示 1～4 天布局，5～7 天可从 4 天样例增加空课程。它不替代正式排课、恢复间隔、器械兼容和时间预算算法。
- 食材只用少量熟制样例演示锁定、替换和整餐重算。过敏原输入界面已设计，完整食材库、过敏校验和生重切换留给正式实现。
- 「帮我估算」展示输入与结果确认结构，结果为样例，不使用身体数据计算个人建议。
- 登录、完成训练记录、草稿保存、审核、回退与工单处理为交互状态或反馈示例；完整数据持久化、服务端鉴权、审计和模型调用未接入。
- 后台部分下拉框用于展示字段和布局，关键可运行样例为模板试排状态、份量试算、审核角色反馈及发布／回退弹窗。
