# 练哪管理后台功能需求 · 重设计版

**版本：V1.0 已确认｜日期：2026-11-18｜适用端：电脑端管理后台**

本次按用户管理、全部动作管理、AI 生成与费用记录、管理人员与操作权限重新组织后台。本文功能已由用户确认，并作为新版后台页面设计依据。此前的第二版小程序业务规则继续作为上下文；后台菜单、字段与操作以本文为准。

用户已明确的必备范围：用户信息与业务数据、收藏记录、训练计划、全部动作、每一次 AI 生成与消费、管理员列表与权限、管理员操作记录。以下页面拆分、字段和操作规则按用户确认的方案执行。

## 1. 后台要能回答的问题

| 管理任务 | 必须能查到的结果 |
| --- | --- |
| 查一个用户 | 谁、何时注册、最近何时使用、拥有哪些器械、收藏了什么、当前练什么、历史完成了什么 |
| 排查用户计划或饮食问题 | 当时输入条件、生成结果、用户实际保存的内容、后续修改、相关版本与 AI 记录 |
| 管理一个动作 | 当前资料和素材、是否对用户展示、是否参与排课、被哪些计划引用、谁修改过 |
| 查一次 AI 生成 | 谁触发、为什么生成、输入输出、调用次数、成功或失败原因、用户是否采用 |
| 查 AI 花费 | 每次调用多少钱、一次生成合计多少钱、每天和每个用户花多少钱、哪些金额尚未结算 |
| 查后台操作 | 哪位管理员何时对哪个对象做了什么，修改前后是什么，是否成功 |
| 管理后台人员 | 有哪些账号、是否启用、能看哪些数据、能执行哪些操作、授权何时发生变化 |

## 3. 用户中心

### 3.1 用户列表

| 类别 | 内容 |
| --- | --- |
| 搜索与筛选 | 用户 ID、昵称；注册时间、最近活跃时间、账号状态；是否有收藏／训练计划／饮食记录；是否调用过 AI |
| 列表字段 | 用户 ID、头像昵称、注册时间、最近活跃时间、账号状态、当前收藏数、有效周计划数、累计完成训练次数、所选周期 AI 生成次数、所选周期 AI 费用 |
| 列表操作 | 查看详情、查看关联业务记录；按权限限制／恢复账号、处理注销申请、导出筛选结果 |
| 空值处理 | 没有昵称或头像时使用默认展示；未提供的性别、身高、体重等显示「未填写」；不要求用户补手机号才能建号 |

用户使用业务 ID 作为后台主键；微信标识只在授权的技术资料中展示，默认脱敏。原本仅存在游客设备的收藏和器械，在同步前后台无法查询，不将其计入账号数据。

### 3.2 用户详情：固定摘要 + 七个标签

顶部固定显示用户 ID、昵称、账号状态、注册与最近活跃时间，并提供跳转到关联记录的入口。

| 标签 | 展示内容 | 允许的操作 |
| --- | --- | --- |
| 基础资料 | 性别、身高、体重及更新时间；过敏原、忌口；账号来源与状态 | 授权查看、添加内部备注；身体数据原则上由用户修改；查看已有的身高／体重更新历史，不补造未采集的数据 |
| 器械与偏好 | 已拥有器械、器械参考图；训练目标、经验、最近使用的天数和时长 | 查看变更历史，跳转关联动作；区分已拥有与某次计划使用的器械 |
| 收藏 | 按部位分组的当前收藏；添加、取消、合并同步事件 | 查看动作详情、筛选历史，不代替用户批量增加或删除收藏 |
| 训练计划 | 当前周计划、历史计划、每日课程、动作和组次、调整历史 | 查看计划详情、对照原始生成版与当前版、查看实际完成记录 |
| 饮食 | 已确认的日能量和三类营养目标、分餐比例、每餐食材重量、生熟状态、锁定值 | 查看目标及搭配历史、关联食材和计算规则、进入不写回用户记录的复算 |
| AI 使用 | 业务生成次数、实际调用次数、费用、成功／失败记录 | 打开对应生成和消费明细，不在此处触发自动重试 |
| 账号与处理记录 | 登录／同步状态、反馈和注销处理、内部备注、账号限制与恢复记录 | 有权人员填写处理原因并执行账号操作 |

**资料与处理边界：** 管理员可以排查记录和维护账号状态；首版不直接覆盖用户已保存的收藏、训练计划、身体资料或实际训练成绩。确需纠错时通过专门的纠错流程，展示对象、原因及前后差异，不做无记录的直接修改。

账号「限制」首版定义为禁止新登录与新业务写入，并使现有登录凭证失效；恢复后用户可重新登录，历史数据保留。与正常用户退出登录、注销申请和数据清理分别记录。

### 3.3 全局收藏记录

分成两个标签，避免把「曾收藏过」误认为「仍在收藏」。

| 标签 | 字段与规则 |
| --- | --- |
| 当前收藏 | 收藏关系 ID、用户 ID、动作 ID／名称、所属部位、首次收藏时间、最近重新收藏时间、同步状态；同一用户同一动作最多一条有效关系 |
| 收藏事件 | 事件 ID、用户 ID、动作 ID、事件类型（添加／取消／游客合并）、发生时间、服务端接收时间、来源端、同步批次、结果 |

支持按用户、动作、部位、事件类型、日期筛选；动作跳转至动作详情，用户跳转至用户详情。取消收藏保留历史事件，但从当前收藏中移除。同步重试使用事件或批次标识去重，不重复增加收藏数量。

热身仍按动作所属部位归类；例如踝关节绕环收藏到臀腿，动态胸部拉伸收藏到胸部。动作分类变更后的当前视图使用当前分类，事件详情保留当时分类。

### 3.4 全局训练计划与实际训练记录

**列表字段：** 计划 ID、用户 ID、周起止日期、训练目标、训练天数、每次预计时长、计划状态、来源、模板／规则版本、创建与最后修改时间、已完成／已安排课程数。

**筛选：** 用户、目标、周日期、来源（规则生成／用户自建／后续扩展的 AI 辅助）、计划状态、是否经过用户修改。

计划状态区分草案、已保存、已归档、已删除；每节训练另有未开始、进行中、已完成、已跳过状态。修改产生版本，不把历史版本当作新的独立计划统计。

详情包含四块：

1. **生成条件：** 当时的目标、天数、时长、经验、器械和偏好快照，引用的模板与规则版本。
2. **七天安排：** 训练／休息、动作顺序、组数、次数或秒数、休息、预计时长，支持打开动作详情。
3. **修改记录：** 调日期、交换日期、换动作、增减动作、改组次、应用范围；展示修改前后值、操作者来源和时间。
4. **实际训练：** 每次训练 ID、开始／结束时间、用时、各组实际次数或秒数、可选重量、完成状态；并列展示计划值与实际值。

调课保留课程 ID，跨周移动可从原周追到目标周。用户完成后修改模板或动作资料，不改写历史计划快照和实际成绩。

**训练模板与个人计划分开维护。** 后台修改系统模板影响之后的新计划，不覆盖用户现有计划。现阶段规则排课不调用模型，不虚构 AI 调用和 AI 费用；以后接入 AI 辅助时才关联生成记录。

### 3.5 饮食记录

按用户、日期、餐次、记录状态筛选。详情显示日目标、三餐目标、所选食材、每项重量和生熟口径、锁定标记、营养汇总、差额、食材与计算规则版本，以及关联的 AI 推荐记录。

区分「AI 推荐的食材」与「用户最终保存的搭配」。AI 成功返回但用户没保存，仍有生成及消费记录，不产生已保存的饮食记录。手动搭配和普通数值复算不记为 AI 调用。

## 4. 动作库管理

### 4.1 全部动作列表

覆盖现有 1,324 个动作，支持后续新增；默认查询全部状态，不能只展示自动排课池或示例动作。

| 类别 | 内容 |
| --- | --- |
| 搜索 | 动作 ID、中文名、原始名称、别名 |
| 筛选 | 训练部位、目标肌群、器械、热身／正式动作、难度、动作模式、上下架、审核状态、自动排课资格、素材或说明缺失 |
| 列表字段 | 封面、动作 ID／名称、部位、目标肌群、器械、动作类型、可浏览状态、可自动排课状态、当前版本、最后修改人／时间 |
| 单项操作 | 查看、编辑草稿、替换封面／动图、提交审核、发布、上下架、查看引用、查看历史和回退 |
| 批量操作 | 批量改分类／标签、设置自动排课资格、上下架、导入、导出；执行前显示命中数量、样例和影响范围，返回逐条成功／失败结果 |

### 4.2 动作详情与编辑

| 区域 | 字段与能力 |
| --- | --- |
| 基础资料 | 稳定动作 ID、名称、原始名称、别名、训练部位、目标及辅助肌群、热身标记、难度 |
| 器械条件 | 必需器械组合、可选器械、已登记替代关系；区分「哑铃和训练凳都要」与「二者任选其一」 |
| 动作说明 | 步骤、要点；保存原始介绍及来源，修订稿与原文可对照 |
| 视觉素材 | 封面、当前动图、原始参考图／GIF；并排预览、分别暂停或播放，查看格式、尺寸、大小和加载状态 |
| 排课属性 | 动作模式、计次／计时、建议组次或秒数、组间休息、预计用时、替换候选 |
| 使用情况 | 当前收藏人数、被引用的模板、未完成计划和历史训练；按权限查看明细 |
| 版本历史 | 修改人、修改时间、修改原因、字段差异、素材版本、审核与发布结果 |

并排播放是辅助核对入口；不把未同步的两个动图宣称为逐帧轨迹一致。是否需要逐帧工具可在后续页面评审中确定。

### 4.3 状态与变更生效

- **用户可浏览**、**可自动排课**分别设置。进入自动排课池需同时满足已上架、已审核、必填属性和素材完整。
- **草稿／待审核／已发布／已退回**是内容版本的审核状态，与动作上下架状态分开。
- 下架后不再进入新推荐和新选动作列表；收藏和未完成计划保留引用并标记「已下架」，提供替换入口，不静默换动作。
- 历史训练保留当时名称、组次、说明及素材版本引用；更正当前动作资料不改变已完成成绩。
- 已被收藏或计划引用的动作不硬删除。只有未发布且未被引用的草稿允许删除；其他情况用下架或归档。
- 发布与回退检查引用和基线版本，记录操作者及原因。批量任务逐条返回结果，不把部分成功显示为全部成功。

### 4.4 分类、器械与模板

维护训练部位、目标肌群、器械名称／别名／参考图、启用状态、排序与关联动作。停用有引用的分类或器械前提示影响范围，不产生无法查询的动作。

模板页面维护每周结构、动作模式、组次范围和时间预算，提供相同条件下的试排。试排结果显示候选排除原因和总用时，保存版本后才影响新计划。热身浏览不受器械筛选；自动安排时优先选当场可做的热身。

## 5. AI 生成记录

### 5.1 一次生成和多次调用的关系

```text
用户的一次生成操作 → 生成记录 G
                      ├─ 调用 A：首次调用
                      ├─ 调用 B：自动重试（若发生）
                      └─ 调用 C：切换备用模型（若发生）
每个调用分别记录用量和费用；G 汇总所有已发生的调用费用。
```

**业务生成记录**回答“用户这次想做什么、最终得到什么”；**模型调用记录**回答“实际请求了哪个模型、用了多少、计了多少钱”。两者通过生成 ID 关联，不能用一条最终成功记录覆盖前面的失败调用。

### 5.2 生成列表

| 类别 | 内容 |
| --- | --- |
| 筛选 | 生成 ID、用户 ID、时间、业务场景、触发来源、结果、模型、提示词版本、是否重试、是否被用户保存 |
| 列表字段 | 生成 ID、发起时间、用户、场景、输入摘要、业务结果、模型列表、实际调用次数、总耗时、采用情况、确认费用、待确认估算、计费完整度 |
| 触发来源 | 用户首次生成、用户主动重新生成、后台测试；自动重试记录在原生成下的调用层 |
| 业务结果 | 排队、处理中、成功交付、生成失败、校验拦截、已取消、规则回退 |
| 采用情况 | 未采用、已保存、修改后保存、未知；与生成成功独立记录 |

生成及调用在请求发出前建立持久记录；进程中断、回调丢失或用量暂缺时保留待核对状态，不能因最终结果未写回而丢失调用。未真正发送的取消请求标记「未调用」，不创建虚构消费。

客户端重复提交同一个请求标识时返回同一生成记录；用户明确点击“重新生成”产生新的生成 ID，并关联上一条。后台重放也创建新的测试生成，注明触发管理员，不能覆盖原记录或用户已有结果。

### 5.3 生成详情

详情页按五个标签组织：

1. **概况：** 用户、场景、触发来源、起止时间、最终状态、耗时、结果关联对象、总费用。
2. **输入：** 当次必要条件快照、用户限制、候选食材或动作编号、模型参数、提示词及规则版本；摘要默认脱敏，详细输入单独授权查看。
3. **输出：** 模型返回的结构化内容、校验后的可交付内容、过滤原因、最终交付内容；按权限查看脱敏请求／响应。记录业务结果，不要求保存模型内部思考过程。
4. **调用时间线：** 每次请求的模型、开始结束时间、成功／超时／错误、重试原因、服务商请求 ID、用量和费用，点击进入消费明细。
5. **用户后续行为：** 是否保存、保存到哪个计划或餐次、是否修改后保存。当前资料与当时快照分开展示。

现阶段主要记录饮食初次推荐、换食材推荐和后台 AI 测试。训练计划按已确认的规则排课；若后续引入 AI，按新场景接入同一套记录。

### 5.4 失败、取消与重复事件

- 调用失败、校验拦截、用户取消或客户端断开均不等于没有费用。
- 已发给服务商的请求即使本地超时，也保留记录，等待用量或账单回补。
- 服务商回调、账单导入重复到达，按请求／账单行标识去重；新增一次真实重试则新增调用记录。
- 生成失败时展示具体原因和是否已回退到手动选择；日志详情可定位原调用。
- 重放前显示将产生新的调用和费用、测试身份与使用版本，需有测试权限并由操作人确认。

## 6. AI 调用、消耗与具体金额

### 6.1 每次调用的消费明细

| 字段组 | 必备字段 |
| --- | --- |
| 关联信息 | 调用 ID、生成 ID、用户 ID或后台测试管理员 ID、业务场景、触发来源、服务商请求 ID |
| 模型信息 | 服务商、计费账号标识、实际模型与版本、模型配置版本、提示词版本 |
| 时间与结果 | 发起／结束时间、耗时、调用结果、错误码、重试序号 |
| 用量 | 输入 Token、输出 Token、缓存命中／写入等服务商计费项；不支持的字段显示「不适用」，未知值显示「待回补」 |
| 价格依据 | 本次适用的单价、计费单位、币种、价格版本与生效时间；按次等计费另列数量和单价 |
| 计算费用 | 按用量及价格计算的原币估算金额、人民币估算金额、换算汇率与日期 |
| 确认费用 | 可归属本次调用的账单实收或扣费金额、原币与人民币值、确认来源、账单行 ID、确认时间 |
| 计费状态 | 未获得用量、仅估算、账单确认、差异待核对；免费调用需有明确的免费依据，不用缺值冒充 0 元 |

列表默认突出展示「确认费用」和「待确认估算」。费用未知的记录明确显示未知，并在汇总中给出未知笔数。

### 6.2 金额计算与显示口径

Token 模型按服务商的互斥计费类别计算：

> 估算费用 = 各计费类别用量 × 该类别单价 ÷ 该类别计费单位之和 + 其他可归属本次的计费项目。

例如缓存命中用量如果已经包含在总输入 Token 中，应先拆出普通输入和缓存输入，不能将总输入计费后再重复叠加缓存命中费用。服务商按次、分层价格或其他方式计费时，使用对应版本的计费规则，不强行套 Token 公式。

规则如下：

- 金额在内部使用高精度十进制保存，先汇总原始精度再按显示精度取整。
- 调用及生成详情显示人民币到 6 位小数；非零但小于显示精度时显示「< ¥0.000001」，避免显示成免费。
- 日／月汇总通常显示到分，可展开原始精度。原币金额、币种和换算依据保留，不能直接相加不同币种。
- 调价后只影响之后适用的调用；历史估算保留当时的价格快照。账单补记通过核对记录反映差额，不抹掉原估算。
- 单次确认金额必须有服务商可归属的数据依据。只有月度汇总账单时，只能确认对应周期总额，单次仍标为估算；如做分摊，显示「分摊金额」，不能标为单次实收。
- 充值金额、余额、购买额度与实际调用消耗分别展示，不把充值直接算作 AI 消耗。退款或账单调整关联原费用单独记录。

**仅用于验收的假设价格示例，不代表任何模型的真实报价：**

| 调用 | 用量与假设单价 | 本次费用 |
| --- | --- | --- |
| 首次请求 | 普通输入 2,000 Token × ¥2／百万；输出 500 Token × ¥8／百万 | ¥0.008000 |
| 自动重试 | 普通输入 1,000 Token × ¥2／百万；输出 250 Token × ¥8／百万 | ¥0.004000 |
| 一次业务生成合计 | 两次调用相加 | ¥0.012000 |

若第一次已账单确认、第二次尚未确认，显示「已确认 ¥0.008000 + 待确认估算 ¥0.004000」，不能把两笔全部标为实际扣费。若首次失败但服务商确认计费，也保留这笔费用。

### 6.3 费用统计与账单核对

| 视图 | 必须支持的维度与指标 |
| --- | --- |
| 总览 | 今日／本月确认消耗、待确认估算、未知费用笔数、调用次数、预算与余量 |
| 按时间 | 日趋势、月汇总；可从金额进入同一筛选条件下的消费明细 |
| 按模型／服务商 | 实际调用次数、用量、费用、成功率、重试费用 |
| 按业务场景 | 初次推荐、替换食材、后台测试等分别统计，生产和测试可分开查询 |
| 按用户 | 生成次数、调用次数、消耗金额、日均消耗、高费用用户排行 |
| 按生成结果 | 成功交付、失败、拦截、取消、规则回退各自已发生费用 |
| 账单核对 | 账单周期、原币、可关联金额、未关联金额、估算差额、处理状态与处理人 |

同一请求跨日结束时，业务生成按发起时间归属；调用消耗趋势按调用发起时间归属，后到费用回补该日。服务商账单同时保留独立的账单周期口径；两者不混用。页面默认北京时间并明确展示时区。

**平均成功生成成本：** 同一统计范围内全部生成费用（包含失败、重试和备用模型）÷ 成功交付的生成次数。仍有费用未知或未结算时标注「估算／不完整」；成功数为零时显示「暂无成功生成」，不显示 0 元。纯规则回退不算 AI 成功交付。

平均成功生成成本按「所选周期发起的生成」作为同一批样本，纳入这些生成关联的全部调用费用，包括跨日重试；页面标注此口径。日消耗趋势则按调用发起日统计，两者不要求逐日金额相等；相同筛选和归属口径下必须能与明细对上。

一个生成有三次调用，生成数是 1，调用数是 3；日/月汇总从消费明细求和，不再把生成汇总金额加一遍。

### 6.4 模型配置与预算

管理模型服务商、启用状态、服务端凭据、默认／备用模型、场景绑定、提示词版本、超时、最大重试次数、单价版本、每日预算、每用户每日额度。

凭据支持新增、轮换和停用，页面只显示脱敏标识。提示词和模型配置先保存草稿，用固定样例测试后发布；历史调用保存所用版本。

预算采用「已发生金额 + 进行中请求预留金额」判断能否继续发起请求；预留按单次上限估算，每次重试也占用额度。预算不足时停止新 AI 请求并提供手动选择，已保存的餐次搭配保留。最终账单存在回补延迟时，页面说明该预算是请求控制值，不承诺账单绝无差异。

### 7.3 权限配置方式

权限分为四层：

1. **菜单：** 能否进入用户、动作、AI、系统模块。
2. **操作：** 查看、新建、编辑、上下架、审核、发布、回退、重放、导出、账号限制等独立配置。
3. **数据范围：** 全部用户、指定用户或关联个案；全部业务或指定场景；生产或测试环境。
4. **字段：** 身体资料、微信标识、AI 详细输入输出、精确费用、服务商配置等单独控制。

角色权限可组合，实际访问必须同时满足操作权限和数据范围；没有匹配授权即拒绝。允许查看汇总不自动允许导出明细。页面隐藏／禁用操作与服务端权限校验同时实现。

权限变更页先展示新增与收回的权限、受影响管理员，提交时填写原因。管理员不能授予超出自己可分配范围的权限，也不能通过编辑自己的角色绕过授权。

## 10. 首版交付与验收

### 10.1 首版必须完成

本轮指定的四类管理能力均纳入首版：用户资料和收藏／计划／饮食查询、全部动作管理、逐次 AI 生成和消费追溯、管理员列表／权限／操作日志。数据概览可先使用表格汇总，但逐条明细不能等到后续版本才补。

推荐开发顺序：

1. 稳定用户／动作／计划／生成／调用 ID，接入管理员身份、权限和操作日志。
2. 用户中心、全库动作及模板管理，保证关键业务记录能查询与关联。
3. AI 生成、调用、计费记录随真实调用同时落库，接入账单核对与预算。
4. 汇总统计、批量维护、导出和页面易用性完善。

| A12 | 修改模型单价后查询历史 | 历史估算使用原价格版本，新调用使用新价格，原始估算与账单差异可见 |
| A13 | 只有月度账单，不能关联到单次调用 | 周期金额可确认，单次维持估算或明确分摊，不伪称单次实收 |
| A14 | 两个并发请求接近预算上限 | 进行中预留计入额度；不足的新请求被停止，重试不能绕过预算 |
| A15 | AI 返回成功但用户未保存；另一次完全手动搭配 | 前者有生成和费用、无已保存餐次；后者有饮食记录但无虚构 AI 消费 |
| A16 | 客服查看模型费用或直接请求无权接口 | 页面和接口均拒绝；授权用户资料仍可按范围查看，拒绝操作被记录 |
| A17 | 管理员权限被收回或账号停用 | 已登录会话不能继续执行被收回的操作，历史操作人信息仍可查询 |
| A18 | 修改动作、导出用户数据、重放 AI、发布与回退 | 每项均能找到管理员、时间、对象、结果、原因或关联上下文；日志不出现明文凭据 |
| A19 | 点击概览费用进入明细，按用户继续筛选 | 同一日期及费用口径下明细与汇总一致；待确认和未知费用不被隐藏为零 |
| A20 | 无成功交付、全为失败或规则回退 | 保留已发生费用；平均成功生成成本显示暂无，生成和调用计数分别正确 |

### 10.3 后续页面设计要求

先绘制用户详情、动作编辑、AI 生成详情、AI 消费明细、管理员权限五个关键页面，验证信息完整性，再补全目录和概览。

- 列表强调搜索、筛选、字段与批量操作；详情标签按业务对象分组。
- 用户详情能完整查看收藏、训练和饮食，不以简短工单弹窗替代。
- AI 费用在列表和详情都有明确金额，不只显示 Token 或用量趋势。
- 模型生成结果、用户保存结果、实际消费和后台处理操作各自可追溯。
- 状态、权限、未同步、未结算、失败及无记录都提供明确页面状态。
