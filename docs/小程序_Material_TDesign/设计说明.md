# 练哪小程序 · Material × TDesign 改版

日期：2026-11-20。依据：2026-11-18 第二版 15 页设计，以及后续“今天训练无需先排一周、连续添加动作应追加而非替换”的用户反馈。

## 打开与交付边界

双击 `index.html` 看全部页面截图；`mobile.html` 可体验交互。保留整个目录即可离线查看；也可运行 `python3 -m http.server 8765` 后访问本地地址。

本次修改的是设计原型。HTML 页面按 TDesign 小程序的组件职责与交互方式设计，使用 TDesign 官方 SVG 图标，并提供 `theme.wxss`。浏览器页面没有加载 `tdesign-miniprogram` 的 WXML 运行时，不能直接作为小程序发布。实际工程需要导入组件、绑定数据并在微信开发者工具验收。本次没有改动线上服务或发布小程序。

## 最小设计简报

- 产品与用户：在家或健身房，想快速挑动作、组织当天训练并查看餐量的人。
- 主要任务：新建今天训练 → 连续选多个动作 → 调整组次 → 保存；次要任务是周安排、动作说明、饮食搭配与收藏。
- 结果：减少选动作时反复跳转和对“添加／替换”的误解。
- 平台：微信小程序；390×844 为主设计尺寸，另查 375 与 430 宽度。
- 气质：日常、清晰、有训练秩序；不做高密度专业健身数据大屏。
- 正向参考：现有练哪品牌与动作媒体；Material 的颜色角色、表面层级、字级；TDesign 的小程序导航、列表、表单和弹层。
- 成功标准：跨分类多选不丢失；第二次加入为追加；替换只影响指定动作；首屏有直接的今天训练入口；主要触控操作清楚。

## 设计语言

保留练哪蓝 `#2448D8`。采用 Material 的 primary / primary-container / surface / surface-container / on-surface 思路，将训练主任务放在浅蓝主色容器，普通数据放在低对比表面，不把所有内容包成同一种卡片。这里是按角色整理的定制色板，不声称由官方动态配色算法生成。

标题 26～29px、分区 19px、正文 13～14px、辅助 11～12px；页面边距 20px，4/8px 间距节奏。大圆角用于今日训练容器和主操作，选择标签采用 9～10px，列表内部用分隔线。品牌标识仅在首页与个人区出现，避免每个子页面重复 Logo。

底部导航保留四项，命名为“今天／训练／饮食／我的”。当前项以浅蓝胶囊背景和文字共同标识。添加与训练编辑状态使用底部提交栏，隐藏底部主导航，留给当前任务足够操作空间。页面保留微信胶囊区域与安全区。

产品特征：训练动作以 01、02 序号和“组 × 次 / 休息”操作条组织，照片负责识别动作，数字负责执行，不用装饰图取代信息。

## TDesign 小程序组件对应

| 设计元素 | 小程序实现建议 | 定制说明 |
|---|---|---|
| 顶部导航 | t-navbar | 保留微信胶囊与安全区，回退明确 |
| 底部导航 | t-tab-bar / t-tab-bar-item | 选中背景按本主题覆盖 |
| 主要／次要按钮 | t-button | 主操作 filled，次操作 outline，圆角按用途定制 |
| 页面列表、个人入口 | t-cell / t-cell-group | 原生小程序跳转，右侧箭头 |
| 动作搜索 | t-search | 搜索名称或部位，空结果提示 |
| 全部／收藏、部位筛选 | t-tabs / t-tag | 部位横向滚动，选择状态可辨 |
| 动作多选 | t-checkbox / t-checkbox-group | 以动作 ID 为 key；已加入不可再选；选中集合独立于筛选结果 |
| 名称、身体资料、目标 | t-input | 持续标签与字段校验；不能只靠 placeholder |
| 数字组次 | t-stepper 或带数值校验的 t-input | 整数、正数与范围校验 |
| 组次／替换菜单 | t-popup + t-cell / t-button | 底部弹层，添加与替换有独立动作标识 |
| 日期调整 | t-date-time-picker / t-calendar | 冲突后明确交换或重新选择 |
| 收藏、状态、提示 | t-icon / t-tag / t-toast | 官方图标，状态同时使用文字 |

版本核对：从 npm 官方 registry 读取 `tdesign-miniprogram@1.18.0` 的主题变量，以及 `tdesign-icons-svg@0.4.8` 的 SVG。`theme.wxss` 使用其公开通用主题变量；`--lianna-*` 是本项目自定义角色变量。每个组件的专用样式覆盖需由开发在当前组件版本复核。

## 核心流程与数据规则

1. 首页“新建今天训练”直接创建空训练，日期默认为今天；本演示固定日期为 2026-11-20。
2. “添加”进入多选模式。看详情、切换分类，已选集合保留。底部显示已选数量与原有数量。
3. 确认后按动作 ID 去重并追加，不改写已有项。再次进入添加时已加入项显示勾选且禁用。
4. 每个动作独立提供组次修改；菜单提供替换、上移和移除。替换必须传入明确的目标索引，禁止缺省替换第一项。
5. 训练名、动作、组次、顺序及收藏和器械保存在当前浏览器 localStorage；并非账号云同步。仅勾选但还未确认加入的候选不作长期保存。
6. 保存后可以继续编辑，也可以体验逐动作训练演示。逐动作完成仅用于交互演示；未实现逐组实绩、暂停恢复与历史快照。

正式开发建议为每节训练、每条动作实例分配稳定 ID，以免排序或异步请求改变索引。追加、替换、移除使用独立事件，服务端按训练版本处理并发。

## 素材与原有功能

沿用项目的 Logo、器械图、10 个动作封面和动图，来源说明保留在 `assets/来源说明/`。饮食资料、每日目标、食材搭配、收藏、登录与记录页面均保留，统一新主题。登录、自动排周和饮食计算沿用示例逻辑，不连接真实账号、AI 或营养服务。不能将示例数字作为个体训练或饮食建议。

## 设计决策记录

- 今天训练优先：依据用户对旧流程过于复杂的反馈；自动排周保留在训练页次级入口。代价是周计划需要多一步进入。
- 保留蓝色品牌：沿用旧版辨识，同时用 Material 的颜色角色重建层级；没有把两个设计系统的默认外观直接拼接。
- TDesign 为组件落地基础：适配微信小程序开发；Material 作为视觉与布局参考，需要主题定制，不能只安装组件就得到本稿。
- 训练编辑采用序号与处方条：动作顺序、组次是健身场景核心信息，直接可改；不增加无关统计卡片。
