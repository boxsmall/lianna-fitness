# 练哪：目标驱动的训练与饮食方案

2026-11-20 · 功能实现版。本文重新设计原 V2 文档第 4、7.3 节及训练目标联动。目标饮食、营养同步、三餐/加餐、体重趋势、次日调整、训练计时和消耗参考已实现；45项回归检查及模拟器主流程通过，正式后台营养规则 v3 已发布。默认数值是产品起始策略，不代表适用于每个人的处方。

## 1. 用户真正需要的结果

用户选择减脂后，应直接知道今天吃多少、每餐选哪些食材及称多少克、今天怎么练，以及一段时间后是否需要调整。目标、身体资料、器械只维护一份，训练和饮食共用；用户不必理解活动系数或自己计算热量缺口。

此前方案仅估算维持能量，训练目标没有进入饮食计算，这是需求层面的缺口。另有代码问题：总能量重算时可能沿用旧的三类营养目标。本次同时修正需求与计算一致性。

减脂以保留肌肉、改善体重与腰围趋势为方向。体重下降不等于下降的全部是脂肪；页面不得根据体重或累计热量推算“已减掉多少脂肪”。

## 2. 简单的用户流程

首次设置三步：

1. 选阶段目标：减脂、维持体重与日常健身、增肌。可选填目标体重；不强迫填写完成日期，也不承诺具体哪天达标。
2. 确认身体资料与生活活动：复用性别、年龄、身高、体重，补充日常久坐/走动情况和通常每周实际训练情况。计划练几天不等于已经练几天。器械默认沿用“我的器械”。
3. 确认方案：显示今日饮食目标、三类营养目标、三餐入口、训练安排；计算说明折叠在“为什么这样安排”里。

后续直接进入“今天”，主要操作只有开始训练、搭配一餐、记录体重。仍允许单独使用训练或饮食，不以填写完整饮食资料阻拦挑动作。

同一阶段目标用于新建训练和饮食方案。改变目标时展示影响并一次确认；临时更换某次训练类型不改变阶段目标。已有手动训练不被自动覆盖。

## 3. 每日能量计算

明确区分三个数：静息消耗估算、全天维持消耗估算、每日饮食目标。首页只突出饮食目标，详情显示计算依据。

### 3.1 初始维持消耗

保留 Mifflin–St Jeor 作为一般健康成人的初始静息能量估算：体重用 kg，身高用 cm，年龄用岁；男性为 10×体重 + 6.25×身高 − 5×年龄 + 5，女性末项为 −161。它预测静息能量，不测量个人真实消耗。[原始研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)

全天维持消耗 = 静息估算 × 已发布的活动系数。活动说明必须覆盖工作、生活走动和通常实际训练，不能只凭健身房次数判断。原有 1.2/1.375/1.55 不直接宣称为临床准确分档；新配置发布前要记录每档适用描述、来源和适用范围，超出覆盖范围的人进入专业目标模式。系统保存首次估算依据，后续结合趋势评估，不频繁按单日活动改系数。

### 3.2 把目标真正计入饮食

| 阶段目标 | 拟采用起始策略 | 用户看到的结果 |
| --- | --- | --- |
| 减脂 | 维持估算 × 85%，即先建立约 15% 缺口 | 每日减脂饮食目标 |
| 维持 | 维持估算 × 100% | 每日维持饮食目标 |
| 增肌 | 对适用的抗阻训练用户，先按维持估算 × 105% 试行 | 每日增肌饮食目标 |

15% 和 5% 是本方案拟定的保守起点，须按适用人群审核、发布和后续校准，不是“医学上人人都该如此”。减脂需要能量缺口，体重下降后能量需要也会变化。[NIDDK](https://www.niddk.nih.gov/health-information/weight-management/adult-overweight-obesity/eating-physical-activity) 增肌不需要追求大幅盈余；小样本抗阻训练研究发现，更快的增重主要增加脂肪积累，不能据此保证更多肌肉增长。[原始研究](https://sportsmedicine-open.springeropen.com/counter/pdf/10.1186/s40798-023-00651-y)

**示例（不是用户个人处方）：** 若全天维持估算为 2400 千卡，减脂起始目标为 2040 千卡，维持为 2400，增肌起始为 2520。三者必须明确不同；界面不能仍统一显示 2400。

只提供一个默认节奏，专业设置中再调整。目标过低、资料异常或不符合通用模型适用范围时，不机械继续减热量。成年非孕哺期、无医嘱限制是自动估算前提；体重过低、有进食障碍风险、特殊疾病等走已有专业目标模式。产品可将女性 1200、男性 1500 千卡设置为保守的自动生成拦截线，须审核后启用；它们不是每个人的安全保证，也不能把结果直接抬到拦截线后假装仍满足原减脂速度。[成人体重管理指南的常用饮食区间](https://pmc.ncbi.nlm.nih.gov/articles/PMC5819889/)

### 3.3 训练日与休息日

默认每天使用同一个经确认的饮食目标，按全周平均活动制定，便于执行。偶尔没练不立即扣餐；练得多不自动增加可吃额度。持续改变训练频率或工作活动时，提出重新评估。

活动系数已涵盖通常训练，因此任何单次训练估算都不得再叠加进维持消耗或饮食额度。这里是防止重复计算，不是否认运动会影响消耗。

## 4. 三类营养与食材份量

对适用的健康抗阻训练用户，拟先按体重确定蛋白质：起点 1.6 g/kg/天；脂肪拟按目标能量的 25%；碳水用剩余能量换算。1.6 是 1.4–2.0 g/kg 参考范围中的产品起点，不是所有人都适用的固定要求。明显高体重、体重过低及特殊健康情况不能机械按当前体重倍乘，需采用已审核的人群规则或专业目标。[ISSN 立场文件](https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/)

计算顺序：确定饮食千卡 → 蛋白质克数 → 脂肪克数 → 碳水克数。普通非训练维持用户使用独立审核的成人营养分配模板，不自动套用运动蛋白质目标。

70 kg、目标 2040 千卡的演示：蛋白质 112 g；脂肪约 57 g；碳水约 270 g。显示整数反算为 2041 千卡，属于取整误差。蛋白质和脂肪先按显示精度取整，再按剩余能量分配碳水；分餐使用余数分配保证合计一致。三类营养反算与目标的显示偏差限定在 10 千卡内；超差不可静默保存。

用户修改体重、活动或阶段目标时，自动模式的千卡与三类营养一起预览、一起确认。手动模式明确标注“已有专业目标”，不悄悄覆盖；若不一致，说明差额并让用户修正。

默认三餐 30%/40%/30%，可调整或预留加餐份额，各餐目标相加必须等于全天。食材优先复用上次搭配，一键重新算份量；展示生重/熟重、可食部分、做法。换一种食材后重新平衡整餐，油、酱料、零食等不能被默认当作零热量。达不到目标的搭配要显示缺口，不能虚构“全部达标”。

保存的是“计划搭配”，只有用户明确记为已吃并确认实际份量后才计入摄入记录；没有实际记录时显示“已安排”，不能显示“已摄入”或“还可以吃”。完整记餐保持可选，不额外强迫逐餐打卡。

## 5. 训练如何服务于减脂

保留当前多选动作、追加不覆盖、已有器械自动带入。减脂方案保留抗阻训练，并按用户时间、能力及已审核模板安排有氧/日常活动。不给每个人套同样天数，不以“消耗越多越好”排序动作。

完成训练展示实际动作、组次、重量和有效时长。现有开始/结束时间可能包含退出、长时间休息，不能当成连续运动时间。新增暂停/继续与分段计时，断线恢复不重复计时；已完成组不被重算覆盖。

单次热量作为参考详情：只有活动类型、适用 MET 条目、体重和对应时长都足够时才展示“估算活动消耗”。统一采用 MET × kg × 小时近似口径；如果显示高于静息的净活动消耗，则采用 (MET−1) × kg × 小时，并清楚标记，两种不能混用。[DGE 运动营养立场文件](https://www.germanjournalsportsmedicine.com/archive-2020/issue-7-8-9/energy-needs-in-sports-position-of-the-working-group-sports-nutrition-of-the-german-nutrition-society-dge/)

抗阻训练按匹配的活动类别评估，不能把某个强度系数乘整个应用打开时间；正常组间休息是否包含在时长中，必须与所用 MET 条目的定义一致，不能重复计入或重复扣除。混合训练只累计可覆盖的片段，并标明覆盖范围。资料不足显示“暂无法估算”，不显示 0、不按组数编造热量，也不据此增加饮食额度。

## 6. 根据实际效果调整

记录体重只需输入一个数，推荐尽量在相近条件下记录。腰围可每周记录一次。体重趋势以两个相邻完整 7 日窗口为基础，各窗口至少 3 个不同日期的有效记录；样本不足显示数据不足，插值不能冒充实际记录。

首次两周观察，之后每周评估。调整还要参考：是否基本按建议份量吃、额外饮食、训练完成、明显饥饿疲劳以及月经/盐分等短期波动。不用一天增重触发降热量，也不根据两次称重反推出精确维持消耗。

| 情况 | 系统行为 |
| --- | --- |
| 趋势符合经审核的个人目标、执行舒适 | 保持当前目标 |
| 连续评估未下降，且记录较完整、确认基本按计划执行 | 建议检查漏记与活动变化，再考虑每天小幅调整，如 100 千卡 |
| 数据不足、执行不明或刚改过目标 | 继续观察，不自动减餐 |
| 下降过快、明显饥饿疲劳或训练表现持续变差 | 暂停继续减量，提示复核方案，必要时转专业支持 |
| 达到阶段目标 | 提议进入维持阶段，由用户确认 |

100 千卡、每次调整后的至少 14 天观察期，均为拟定产品节奏，可由审核规则调整。系统给出建议和原因，用户一键接受后从次日生效；不在后台无提示改变今日份量。体重下降速度不能保证，长期趋势用于修正起始估算。[CDC 体重管理建议](https://www.cdc.gov/healthy-weight-growth/losing-weight/index.html)

## 7. 首页和后台

首页示例：

> 当前目标：减脂  
> 今日饮食目标：约 2040 千卡（估算起点）  
> 蛋白质 112 g · 碳水 270 g · 脂肪 57 g  
> 早餐 / 午餐 / 晚餐：选食材，查看克数  
> 今日训练：按我的器械安排，或自己多选动作  
> 体重趋势：记录不足，暂不调整

“为什么是 2040”详情显示：维持估算 2400 − 计划缺口 360 = 2040，已考虑通常活动，当前训练估算不会重复计入。

后台新增目标策略配置、适用条件、营养分配、调整条件、来源与版本；每条规则保留审核发布、回退能力。用户详情可以复算当时使用的身体资料、阶段目标、活动选择、计算参数、精确值及取整结果。不能把“已审核”当作“测量准确”的证明。

DeepSeek 只负责解释、候选食材搭配及措辞。能量、营养、份量、目标调整条件由服务端确定性规则计算；AI 不可更改公式、突破边界或填补未知数据。

## 8. 数据、迁移与开发顺序

增加阶段目标与生效日期、能量方案快照、营养模式、体重日记录、可选腰围与执行反馈、调整提议、训练分段时间。所有写入复用账号鉴权、版本冲突检查和幂等机制。

历史饮食和训练保存原始快照；新规则不回写过去。老用户显示原已确认目标，提示根据阶段目标重新评估；训练目标与饮食目标原本不一致时由用户确认，不偷偷切换。只改分餐比例不重新估算全天能量、不改变来源和版本。前后端共享同一计算结果和规则版本。

按依赖顺序交付完整流程：

1. 统一阶段目标、能量/营养引擎、现有营养不同步修复、后台规则编辑与试算。
2. 首页与饮食确认、食材份量联动、老用户迁移、当天训练兼容。
3. 体重趋势、执行反馈、调整提议和历史追溯。
4. 训练分段计时及有依据的消耗估算；不足信息时保持明确的不可估算状态。
5. 回归测试、真实模拟器完整走通，再部署后台、上传小程序；报告区分上传与体验版生效。

## 9. 必须通过的验收

| 用例 | 通过条件 |
| --- | --- |
| 同一维持估算 2400，切换减脂/维持/增肌 | 默认策略分别为 2040/2400/2520；切换一次确认生效 |
| 体重变化后重新估算 | 总千卡与三类营养同步，无旧值残留 |
| 修改分餐比例 | 全天目标、估算来源不变，分餐加总一致 |
| 完成一次训练或当天漏练 | 不重复增加消耗、不自动奖惩饮食额度 |
| MET 示例：70 kg、3 MET、半小时 | 总消耗近似 105 千卡，净活动约 70；标注口径且不加入饮食额度 |
| 训练挂后台、暂停、断线续练 | 不把全部墙钟时间当作运动；时段不重复 |
| 保存搭配但未确认已吃 | 不写为实际摄入 |
| 换食材、锁定克数、油脂取整 | 按最终显示份量计算；生熟数据不混用；过敏过滤继续有效 |
| 一天增重、少量体重记录、经期波动标记 | 不直接降热量或宣称减脂失败 |
| 足够记录且符合调整条件 | 解释原因，经用户确认后次日生效；等待观察期 |
| 特殊人群、单位错误、低于策略拦截线 | 不输出貌似正常的自动减脂方案；给出可理解原因 |
| 旧版账号、跨端冲突、发布回退 | 已确认方案和历史可复核，拒绝覆盖较新数据 |
| AI 返回错误数值 | 不影响确定性计算，不向用户冒充审核结果 |

准确性的验收分为两层：工程层保证公式、单位、目标联动与数据一致；个体层承认初始估算误差，靠足够的趋势和执行反馈逐步评估。产品不承诺首次计算就是实测消耗，也不承诺按计划执行必然按指定速度减脂。

## 实现范围补充

自动目标采用18至64岁、BMI 18.5至不足30的产品适用范围；范围外仍可填写已有专业目标。单次活动参考采用2024成人活动汇编的19至59岁范围，仅支持匹配的常规抗阻/自重活动；混合训练或资料不足显示无法估算。长时间离线计时自动停止累计，恢复后需确认继续。保存搭配与摄入分开快照，后台查看新增身体记录沿用敏感资料授权。
