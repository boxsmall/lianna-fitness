# 练哪后台重设计稿

依据用户确认的《练哪管理后台功能需求 · 重设计版》制作，面向电脑端后台管理。此版重点展示用户业务数据、完整动作目录、AI 逐次生成和费用，以及管理员权限与操作日志。

## 打开方式

- 双击 `index.html`，进入可点击后台，默认打开用户列表。
- 双击 `页面总览.html`，通过缩略图选择页面。
- 所有脚本、封面、截图和样例动图均在目录内，可离线打开，无需安装依赖。
- 交互状态只存在于本次页面会话，刷新恢复演示初始数据。

## 页面结构

| 模块 | 主页面 | 详情与标签 |
| --- | --- | --- |
| 数据概览 | 运营概览 | 待处理事项与对应业务明细 |
| 用户中心 | 用户列表、收藏记录、训练计划、饮食记录 | 用户详情七个标签；计划的日期安排、生成条件、修改记录、实际训练；饮食保存值与复算 |
| 动作库管理 | 全部动作、部位肌群器械、训练模板规则 | 动作资料与素材、排课属性、使用引用、版本发布 |
| AI 中心 | 生成记录、调用消费明细、费用统计、模型配置 | 生成概况、输入快照、输出校验、调用时间线、采用情况；单次调用计费依据 |
| 系统管理 | 管理人员、角色权限、操作日志 | 管理员详情、授权变更确认、操作前后差异 |

共 15 个主菜单，另有用户、计划、饮食、动作、生成、调用、管理员详情。详情里的标签对应独立信息区域，不再把用户业务数据压缩到一张工单弹窗中。

## 这版设计的组织方式

1. **从用户查完整业务。** 用户详情固定展示账号摘要，七个标签分别承载资料、器械偏好、收藏、计划、饮食、AI 和账号处理。收藏、计划、生成、消费使用相同 ID 关联。
2. **全库动作可查。** 直接载入项目的 1,324 条动作与对应封面，可搜索名称或 ID、组合筛选部位与器械、分页和选择批量操作。上下架与自动排课是独立状态。
3. **AI 过程与消费分开。** 一次生成下保留多个实际调用；确认费用、待确认估算、未知费用分别显示。详情保留用量、当次单价、价格版本和账单状态。
4. **按对象记录操作。** 权限变更、动作发布、下架、后台测试、账号处理等写入本地演示日志，日志详情展示前后差异。
5. **使用桌面信息密度。** 1440 × 1000 为主要画布，1280 宽度检查通过。分组导航、紧凑表格、顶部筛选、宽主栏与关联侧栏。金额使用等宽数字，待确认使用暖色辅助区分。

视觉延续现有蓝色、Logo 和动作人物；布局依据本次后台任务重排。白色表格用于记录查询，浅蓝费用区用于突出本次生成的成本拆分，颜色始终配文字状态。

## 建议先体验的路线

### 1. 用户数据

用户列表 → 林小满 → 收藏记录 → 按臀腿筛选 → 查看站姿踝关节绕环；再进入训练计划 → P301 → 修改记录和实际训练。

基础资料中的「授权查看」会弹出填写访问原因的窗口，并写入演示日志。右上角切换客服角色可查看权限拒绝反馈。

### 2. 全部动作

搜索 `0859` 可找到目录末尾的腕力滚轴训练；组合「肩部 + 哑铃」筛选；打开侧平举，核对原版和重制媒体，修改说明、保存草稿、提交审核、批准发布。

下架已收藏的侧平举后，用户收藏仍保留该动作，并显示已下架状态。演示操作不会修改项目正式动作文件。

### 3. AI 生成与费用

生成记录 → G8001 → 看到两次调用合计 ¥0.012000，其中 ¥0.008000 已确认、¥0.004000 待确认 → 调用时间线 → C9002 → 单次计费依据。

费用统计 → 账单核对 → 关联 C9002 演示账单：确认金额增加，待确认减少，总费用不重复增加。C9006 保留未知费用，不显示为免费。

「重放为测试请求」创建新的测试生成和调用，并关联原生成；不覆盖原来结果。所有模型与单价都是用于展示计算方式的假设样例，不发起真实付费调用。

### 4. 管理员与日志

管理员列表 → 新建账号／停用账号；角色权限 → 勾选权限 → 检查新增和收回项 → 填写原因保存 → 操作日志查看前后差异。

最后一名超级管理员不能停用。切换客服角色后，消费明细、模型配置和管理员管理显示权限提示；日志、权限和身份均为浏览器端交互演示。

## 实现范围

- 动作名称、说明、分类、器械和封面来自现有项目；动作状态及排课审核状态为演示值。不是对现有线上全库状态的核验。
- 载入了全部 1,324 条动作和封面；为控制设计包体积，只打包 10 个动作的动态演示及原版参考。其余详情明确展示封面与未打包提示。
- 用户、计划、饮食、AI、价格、账单、管理账号和操作日志均为虚构样例。主要联动围绕 U10001 / P301 / M501 / G8001 / C9001、C9002 展开。
- 搜索、核心筛选、分页、关键详情跳转、动作草稿与发布状态、账单确认、重放、新增管理员、角色操作权限、下架引用和日志反馈可操作。
- 模板与营养规则编辑、价格版本、分类维护等次要配置展示草稿与确认流程，不是完整业务引擎。模板试排用固定可行／超时样例，饮食复算用固定食材数据。
- 数据范围选择展示授权设计；真实数据范围隔离、服务端鉴权、数据库持久化、登录会话、账单接口和生产发布需在开发阶段实现。不能把前端角色演示当作安全边界。
- 浏览器直接打开本地文件时，动图静态预览可能使用对应原版首帧；通过本地 HTTP 访问时可抓取当前显示帧。此处不提供逐帧同步校对。

## 设计验证

| 检查项 | 结果 |
| --- | --- |
| 用户任务与入口 | 用户、动作、AI、系统管理均有独立导航；关键记录可互相跳转 |
| 品牌与视觉 | 复用现有 Logo、主蓝和人物素材，采用适合后台密度的分组导航与表格 |
| 排版 | 修复详情分栏；宽主栏承载明细，右侧用于摘要与关联记录；表格超宽时在容器内滚动 |
| 核心交互 | 用户收藏归类、完整目录搜索筛选分页、草稿发布下架、费用核对、重放、管理员创建及权限拒绝已检查 |
| 页面状态 | 展示无匹配结果、待审核、已下架、未知费用、生成失败、校验拦截、权限拒绝与原因必填 |
| 数据口径 | G8001 的两笔费用和合计一致；账单确认转换不改变总额；失败调用保留费用；未确认用量不当作零 |
| 桌面适配 | 主页面在 1440 宽度截图，详情标签检查 1280 与 1440 宽度，无页面级水平溢出 |
| 资源 | 检查 1,324 个封面和代表性动图；离线入口与播放控件无脚本异常 |
| 真实服务验收 | 本轮不适用；这是供页面和操作流程评审的设计原型 |
