# 练哪二版业务服务和管理后台

小程序、桌面管理界面和回归测试共用同一套排课及营养计算代码。使用 Node.js 24 和 SQLite。服务读取同一仓库的小程序动作目录，以及「动作库」中的媒体供后台对照。首次启动自动创建数据库和待审核草稿。

## 本机启动

在 PowerShell 中进入仓库的「二版后台」目录。先创建本地管理账号，命令会单独提示输入密码。运营、审核、客服角色可以随后由管理员在「用户与反馈」中分别创建。个人开发时可为同一账号指定多个角色。

```powershell
.\设置后台账号.ps1 -Name owner -Roles '管理员,运营,审核,客服'
node server.js
```

浏览器打开 [本机管理后台](http://127.0.0.1:8786/)。运行测试使用 `node --test v2.test.js`，测试数据使用内存数据库。业务库默认位于 `runtime/lianna.sqlite`，此目录已被 Git 忽略。可用 `LIANNA_DATA` 指定持久化目录。备份应使用一致的 SQLite 快照，包含训练和饮食个人资料的数据库仅交给获授权人员。

## 小程序和微信登录

微信开发者工具照常导入「微信小程序」目录。默认首页为「今天」。游客可以访问动作库、筛选和收藏。应用在开发者工具中默认尝试端口 8786，微信的合法域名校验可能拒绝本机 HTTP 地址。真机联调时应部署业务服务，经 HTTPS 反向代理提供服务，在微信后台登记 request 合法域名，并保留动作媒体的 downloadFile 合法域名。

业务域名填写在 `微信小程序/miniprogram/lib/service.js` 顶部的 `apiOrigin`，第三方平台接入也可提供 `extConfig.liannaApi`。服务端读取 `LIANNA_APP_ID` 和 `LIANNA_APP_SECRET`。小程序用 `wx.login` 换取临时凭证，业务服务向微信换取 OpenID，然后签发有期限的业务令牌。生产服务没有测试账号登录接口。服务默认绑定回环地址；反向代理在另一容器时可通过 `LIANNA_BIND` 和 `PORT` 设置监听地址与端口。

## 内容首次启用

1. 在「动作与器械」打开初始草稿，核对原版、重制演示、器械、动作模式、难度、每次用时、替代动作和说明。可以从完整的 1,324 个动作中选取条目。只有已审核、允许浏览且启用自动排课的动作会进入试排。「热身」也是需核对的排课模式。
2. 运营保存草稿并提交，具备审核角色的人员填写原因、批准发布。随后可以在「训练计划」试排及发布周模板。草稿试排不写入任何个人计划。
3. 食材草稿覆盖 24 类食材。区分熟食、生重及原包装称重口径。每条都保留来源、版本及每百克营养值。馒头对应特定品牌规格。初始数据使用 USDA SR Legacy 和 Hakka 产品标签。过敏原的「已核对」列表需要逐项核实；用户标记了某种过敏原时，相关状态未知的食材也会被排除。[USDA 数据下载](https://fdc.nal.usda.gov/download-datasets/) · [Hakka 产品标签](https://www.hakka.com.au/shop/item/hakka-plain-mini-mantou-500g)
4. 在「食材与饮食规则」审核分餐、比例和能量估算配置。自填专业目标可独立使用。估算草稿默认关闭，启用前由营养审核人员核对适用人群、计算依据、参数和活动等级。历史计划与餐次保留保存时的副本和版本。
5. 图文更新可在动作条目的 `media` 下成套填写 `cover`、`animation` 两个 HTTPS 地址，以及 `coverHash`、`animationHash` 两个文件的 SHA-1。小程序校验完整后切换本地目录。回退生成新的发布版本，已核实的食材过敏原风险继续保留。

## AI 与运维

配置 `LIANNA_AI_URL` 为实际供应商的完整 HTTPS Chat Completions 接口，并在「AI 推荐与用量」草稿填写模型、提示词、每日调用上限和每百万输入/输出 token 的价格。建议同时填写计价单位对应的价格。无密钥、超额、超时或模型返回候选集外的编号时，客户端仍可手选和计算。

模型密钥可通过服务端环境变量 `LIANNA_AI_KEY` 提供。若希望管理员在界面轮换，另行配置独立的 `LIANNA_MASTER_KEY`（32 字节随机值的 64 位十六进制表示），业务库保存 AES-GCM 密文。密钥不要写入客户端和仓库。客户端提交的食材克数由业务服务重算。AI 接口仅接收餐次、候选编号、名称及用户选择提供的口味提示。

工作台按北京时间日期查看失败和发布记录。工单由管理员分派，客服按工单授权查看所需个人资料。注销请求先登记工单，随后由管理员处理。用户提交的数据带版本号和请求编号，重复写入具有幂等性，遇到多端版本冲突要求重新载入。
